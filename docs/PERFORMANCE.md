# macOS 原生编辑器性能记录

2026-11-26。本机 Apple M4 Pro，64 GiB 内存，macOS 27.2.1，arm64 Release。Scoop 工具链的源码提交为 `24cdad0e5`。

每份初始文档为 299,999 个 UTF-8 字节。样本一有十万条两字节的短行，以 LF 分隔。样本二将这些 LF 原位替换成空格，形成同样大小的单行。两种样本均含 100 处字面串 `XY`，使用相同的 640 × 350 逻辑像素窗口、14 点 Menlo 和关闭软换行的配置。

首版基线的每种样本各启动三个新进程。本文末尾的两批功能复测还比较同一版本的普通视图和启用扩展的视图，分别测量选择与命中。表中耗时为单调时钟测得的中位数，内存为三个进程截至该阶段的最高驻留内存（RSS），含 AppKit、图形库和 Scoop 运行时。前两项在挂载前测量。标有“到呈现”的项目等到与该次操作匹配的 Accepted 帧，含原生事件分发和 5 ms 定时唤醒带来的等待。

| 操作 | 十万短行 ms | 十万短行 MiB | 单条长行 ms | 单条长行 MiB |
| --- | ---: | ---: | ---: | ---: |
| 从内存中的 UTF-8 构造文档与行索引 | 3.61 | 21.7 | 0.78 | 19.1 |
| 从文档读取完整字符串 | 2.99 | 22.6 | 1.19 | 20.1 |
| 挂载到首个已呈现帧 | 72.39 | 104.5 | 127.03 | 235.2 |
| AppKit 键入一个 ASCII 字符到呈现 | 4.75 | 107.3 | 67.51 | 336.9 |
| 显示拼音组合串、提交“中”到呈现 | 15.13 | 112.0 | 161.28 | 366.5 |
| 滚动请求到呈现 | 3.33 | 112.9 | 6.71 | 367.4 |
| 同一事务替换 100 处到呈现 | 8.00 | 117.2 | 94.30 | 374.6 |
| 撤销该事务到呈现 | 6.88 | 119.1 | 94.12 | 387.3 |
| 从 AppKit 查询已发布的完整无障碍值 | 0.26 | 119.1 | 0.26 | 387.3 |
| 选中全文并生成输入法上下文 | 2.10 | 120.3 | 1.88 | 387.3 |

滚动距离为 800,000 个逻辑像素，短行纵向滚动，长行横向滚动。全部替换将 100 个 `XY` 换成 `ZZ`，撤销后恢复 100 个匹配，耗时包含查找扩展的高亮更新。打开文档的时间从宿主已持有字符串开始计算。

## 输入法与无障碍的复制范围

| 读取时机 | 十万短行 | 单条长行 |
| --- | ---: | ---: |
| 首次聚焦时的输入法片段 | 2 B | 299,999 B |
| 编辑后选中全文的输入法片段 | 300,003 B | 300,003 B |
| 编辑后辅助技术读取的完整正文 | 300,003 B | 300,003 B |

普通光标的输入法上下文随当前逻辑行长度变化。选中全文时，覆盖主选区的逻辑行也覆盖全文。辅助技术需要的完整字符串按文档版本物化，随后 AppKit 可以读取已发布的值。表中分别列出了两项成本。单条长行的每次正文修改还需重新排版整行。

在有桌面会话的 macOS 上从仓库根目录运行以下命令，可得到每次测量的微秒数、累计峰值 KiB 和相关 UTF-8 字节数。

```sh
./validation/appkit.sh benchmark
```

## 两批功能完成后的复测

在同一台设备上使用 Scoop `13a8be70b` 和同一个 Release 可执行文件，四种组合各启动三个新进程。扩展列开启逐行 Scoop 着色，安装 100 条诊断、一个首行 CodeLens、一个行内参数名提示及一个局部粗体。前两项结果使用与首版基线相同的内存正文，下面以毫秒列出中位数。

| 操作 | 十万短行，普通 | 十万短行，含扩展 | 单条长行，普通 | 单条长行，含扩展 |
| --- | ---: | ---: | ---: | ---: |
| 打开文档模型 | 1.15 | 1.16 | 0.88 | 0.88 |
| 读取完整字符串 | 1.42 | 1.21 | 1.19 | 1.19 |
| 挂载到首帧 | 71.53 | 73.43 | 127.48 | 137.94 |
| 键入一个 ASCII 字符到呈现 | 3.88 | 4.28 | 65.62 | 71.78 |
| 中文组字及提交到呈现 | 23.10 | 20.63 | 155.29 | 160.65 |
| 滚动到呈现 | 2.61 | 67.60 | 6.79 | 2.31 |
| 在窗口坐标命中 500 次 | 0.23 | 0.22 | 71.98 | 72.22 |
| 改变可见选区到原生 caret 对齐 | 2.77 | 3.96 | 24.86 | 24.60 |
| 替换 100 处到呈现 | 5.98 | 9.21 | 107.29 | 117.22 |
| 撤销 100 处到呈现 | 6.85 | 6.95 | 105.81 | 117.69 |
| AppKit 读取无障碍全文 | 0.34 | 0.34 | 0.26 | 0.34 |
| 全选并生成输入法上下文 | 1.55 | 1.61 | 1.58 | 1.56 |

四列的进程峰值 RSS 依次为 125.9、133.0、396.7、370.0 MiB。首次聚焦时，普通和扩展视图的输入法片段在短行样本中都是 2 B，在单行样本中都是 299,999 B。全选后四组均为 300,003 B。

命中取自滚动后可见源码行内部，在一帧上反复查询。选区测量从设置选区起，到显示该选区且原生 caret 与实测字形对齐为止。三个进程的样本量适合比较这两种文档形状，不能用来估计尾延迟。

首轮复测发现，词法器为每个标识符重复复制了整行。词法扫描与带样式的分段排版改为复用行字节后，开启扩展的长行键入从 2,568.23 ms 降至 71.78 ms。单行的字形排版与输入法上下文仍覆盖整条逻辑行。
